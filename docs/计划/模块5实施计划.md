# 模块 5 可观测性、故障注入与性能验证实施计划

> 给执行者：本计划按任务逐项执行，默认使用测试驱动开发。每个任务先写失败测试，再实现最小代码，最后运行该任务的定向测试和必要的全量回归。任务全部完成后暂停，等待模块级人工审核；不自动提交 Git。

**目标：** 在不改变模块 4 状态机、租约所有权和恢复语义的前提下，为控制面和 Worker 增加结构化日志、低基数指标、OpenTelemetry 调用链、可验证告警、测试专用故障注入以及可复现的性能和故障报告。

**架构：** 新增观测组件位于 internal/observability，通过明确的 Logger、Metrics、Tracer 边界被 HTTP、Coordinator、Repository 和 Worker 调用。告警位于 internal/alerting，只消费聚合快照并通过 AlertSink 通知；故障注入位于 internal/faultinject，只通过构造函数注入到测试夹具。PostgreSQL 和既有工作流状态仍是业务事实源，观测失败不得阻塞状态提交、租约续期或结果完成。

**技术栈：** Go 1.26；标准库 log/slog、context、net/http、testing；Prometheus 官方 Go Client；OpenTelemetry Go API/SDK、stdout exporter 和测试用 SpanRecorder；PostgreSQL 16；Docker Compose；现有多进程 Worker 测试夹具。

**执行状态：** 模块 5 工程实现、八类故障实验、五类告警 E2E、24 组五轮性能矩阵、学习文章、自动化质量门禁和提交前终审已于 2026-08-26 完成；用户手动提交、文章最终阅读和发布尚未完成。

## 全局约束

- 代码标识符保持英文，关键字段、锁、事务、生命周期和故障边界使用规范中文注释。
- 默认测试不访问外部网络，不依赖真实模型 API，不发送真实邮件、短信或企业 IM。
- 不把 run_id、task_key、attempt、worker_id、dispatch_id 或用户输入作为 Prometheus 标签。
- 不新增生产故障注入 HTTP 路由，不从公开请求体接收故障计划。
- 日志、Trace 和告警不得写入 Token、密码、租约令牌、模型 API Key、完整任务输入或敏感结果。
- 观测组件出现错误时，核心状态机、事务、租约和结果幂等行为必须保持不变。
- 不引入 Kafka、Redis、NATS、Alertmanager、Jaeger、Tempo 或 Grafana 服务。
- 依赖必须选择与 Go 1.26 兼容的稳定版本，并在 go.mod 中记录；依赖变化后重新运行全量测试和文档验证。
- 不自动提交、暂存或创建 PR；模块完成后由用户手动提交。
- 学习文章只能使用已经发生的代码和实验，不能把计划写成已完成事实。
- 每个新增命令都必须在命令块外逐条解释，命令块内只保留可执行命令。
