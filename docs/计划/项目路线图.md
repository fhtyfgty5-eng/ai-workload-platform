# 项目路线图

## 执行原则

- 按模块推进；
- 每个模块先学习、再制定详细计划、再使用 TDD 实现；
- 每个模块完成后暂停，等待用户人工审核；
- 未获得用户批准，不进入下一模块；
- 不自动提交 Git；
- 不自动创建 Pull Request 或公开仓库。

## 模块 0：项目定义与交接基线

目标：让项目价值、用户、范围、架构、术语和低成本验证方式清晰可理解。

交付物：

- 项目上下文；
- 产品说明；
- 架构基线；
- 范围决策；
- 学习资料规范；
- 项目路线图。

验收：用户能够用自己的语言说明项目解决的问题，并批准模块 1 的范围。

## 模块 1：单机可靠工作流内核

目标：不依赖容器、云服务和真实模型，实现单机环境下的任务定义、状态转换、依赖、重试、超时、取消和恢复。

默认资源：Go、标准测试工具、Mock Agent、本地持久化接口。

## 模块 2：自然语言工作流草稿与校验

目标：让用户用自然语言描述目标，由 Agent 生成结构化工作流草稿，并在执行前完成依赖、参数、权限和资源校验。

验收：缺少关键信息时系统会追问；校验不通过时不能执行；用户可以查看并修改草稿，确认后生成正式版本。

## 模块 3：多节点执行与故障恢复

目标：实现节点注册、心跳、任务租约、重新分配和多 Worker 并发执行。

验证：多进程模拟节点，不要求真实云服务器。

## 模块 4：受限执行环境

目标：使用本地容器运行时限制任务资源和权限，明确安全边界。

前置条件：安装并验证 Docker Desktop、Colima 或其他合法容器运行时；是否引入 Rust单独评审。

## 模块 5：可观测性与故障实验

目标：建立日志、指标、调用链、告警和可复现故障实验。

## 模块 6：AI/Agent 执行适配

目标：在 Mock Agent 之外，接入至少一个合法的模型接口或本地模型，并验证单 Agent 与多 Agent 工作流。

成本控制：真实模型测试默认人工触发、低并发并设置预算。

## 模块 7：搜索/推荐数据流水线案例

目标：以模拟公开数据完成数据处理、索引更新、检索和评测工作流，用于验证平台承载数据任务的能力。

## 模块 8：本地 Kubernetes 与资源调度

目标：在单机轻量集群中验证部署、资源限制、节点选择和故障恢复，不依赖付费云资源。

## 模块 9：产品化与公开准备

目标：完善安装方式、控制台、SDK、示例、压测、故障报告、许可证和安全说明，并评估是否公开仓库。
