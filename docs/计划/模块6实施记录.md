# 模块 6 受限执行环境与 Kubernetes 实施记录

> 本文记录模块 6 的实际实施结果。需求边界、技术选型和验收标准以[模块 6 需求与设计](模块6需求与设计.md)为准，实际实验数据以[模块 6 验证报告](../实验/模块6验证报告.md)为准。

Task 1 至 Task 8 保留关键接口和测试边界，便于追溯实现过程；它们不是当前待办清单，模块最终状态以本文末尾的“实施结果”和验证报告为准。

**目标：** 在不改变模块 1 至模块 5 的工作流状态、租约所有权、恢复和观测语义的前提下，为 Worker 增加基于固定 Action 注册表的受限容器执行，并用 Docker Desktop 与本地 kind 集群验证资源、权限和故障边界。

**架构：** 工作流内核只认识有限 ExecutorKind 和结构化 ExecutionResponse；Action 注册表把公开动作名映射为固定执行描述；Docker 与 Kubernetes 执行器分别通过可替换运行时客户端管理容器或 Job/Pod 生命周期。PostgreSQL、Attempt、Dispatch 和租约仍是业务事实源，容器 ID、Pod 名称和运行时日志只用于诊断。

**技术栈：** Go 1.26；Docker 官方 Go SDK；Kubernetes client-go；Docker Desktop；kubectl；kind；PostgreSQL 16；现有 Worker、Coordinator、faultinject、observability 和多进程 E2E 夹具。

**阅读说明：** Task 内保留关键实现边界和实际结果；方括号中的步骤是历史实施记录，不是当前待办。未完成的资源、网络和完整 Worker 恢复实验以文末“执行记录”和模块 6 验证报告为准。

**接口和不变量：**

    type ExecutorFactory interface {
        ForKind(workflow.ExecutorKind) (workflow.Executor, error)
    }

    type RuntimeOptions struct {
        Executors ExecutorFactory
        ...
    }

    注册时 ExecutorKinds 必须声明 Worker 实际支持的执行器类型。
    Claim 返回的 Lease.ExecutorKind 必须在该 Worker 能力集合中。
    不支持的 ExecutorKind 不能被静默降级到 mock。
    租约取消、AttemptDeadline 和 Worker ShutdownTimeout 必须传递给容器执行器。

**步骤：**

- 写失败测试：Worker 注册同时声明 mock/container；收到 container Lease 时调用 DockerExecutor；收到不支持类型时返回明确错误并不提交 Complete。

- 写失败测试：现有 mock Worker 和模块 1 至模块 5 CLI/HTTP 演示保持兼容。

## 关键边界

- 当前 Kubernetes 验证路径是本机 Go Worker 通过 kubeconfig 调用集群 API，不提供可直接部署的控制面或 Worker Deployment。
- Action 只能来自固定注册表；容器不是绝对安全沙箱，不承诺恶意代码隔离、多租户安全或生产 Kubernetes 高可用。
- 具体原始输出、环境版本和剩余实验见[模块 6 验证报告](../实验/模块6验证报告.md)。
