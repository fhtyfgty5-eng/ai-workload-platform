# 模块 7：真实场景、最小控制台与开源发布实施计划

> **For agentic workers:** 本计划按任务逐项执行。行为变更使用 TDD；每个任务完成后运行该任务的验证命令，整个模块完成后等待用户统一人工审核。不得自动提交 Git、创建 Pull Request 或公开发布。

**目标：** 在现有 Go 控制面和 Worker 之上交付一条可在浏览器中完成的自然语言草稿、人工确认、可靠运行和观测闭环，并补齐前端工程、CI/CD、部署文档和开源治理。

**架构：** Go 控制面继续作为唯一业务事实源。新增 Draft API 只适配已有 `agent.Service`，草稿不落 PostgreSQL；React/TypeScript/Vite 控制台位于独立 `web/`，通过 HTTP/JSON 调用版本化 API，Token 仅保存在当前浏览器标签页的 `sessionStorage`。

**技术栈：** Go 1.26、现有 PostgreSQL/HTTP/OpenAPI/Worker；Node.js 24 LTS、React、TypeScript、Vite、React Router、原生 `fetch`、`lucide-react`；Vitest、React Testing Library、JSDOM；GitHub Actions、npm lockfile。

## 全局约束

- 控制台不直接连接 PostgreSQL、Docker Engine 或 Kubernetes API。
- 前端不复制 DAG 校验、状态转换、重试、取消、租约或恢复逻辑。
- Draft 必须经过服务端校验和 `content_hash` 确认；模型输出不能直接执行。
- 默认模型为离线 Mock Model；真实模型只能由服务端显式配置，API Key 不进入浏览器。
- viewer 只能查询；operator 才能生成/校验/确认草稿、创建 Workflow、启动和取消 Run。
- 草稿只在请求和浏览器会话中存在，不新增 Draft 数据库表或迁移。
- 写请求使用新的幂等 Key；前端不得重试不明确结果的写请求。
- 轮询使用可取消请求和固定间隔；不提前引入 WebSocket/SSE。
- 默认测试不访问外部网络、不访问付费模型、不依赖本机 Docker Desktop 或 kind。
- 学习资料面向零背景读者，首次出现的专业名词必须解释并说明未选同类方案的原因。
- 关键 Go 结构体字段和复杂函数内部使用规范中文注释；代码标识符保持英文。
- 不提交 Token、密码、公司信息、业务数据、本机绝对路径、`node_modules` 或构建产物。
