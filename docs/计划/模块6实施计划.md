# 模块 6 受限执行环境与 Kubernetes 实施计划

> 给执行者：本计划按任务逐项执行，默认使用测试驱动开发。每个任务先写失败测试，再实现最小代码，最后运行该任务的定向测试和必要的全量回归。任务全部完成后暂停，等待模块级人工审核；不自动提交 Git。

**目标：** 在不改变模块 1 至模块 5 的工作流状态、租约所有权、恢复和观测语义的前提下，为 Worker 增加基于固定 Action 注册表的受限容器执行，并用 Docker Desktop 与本地 kind 集群验证资源、权限和故障边界。

**架构：** 工作流内核只认识有限 ExecutorKind 和结构化 ExecutionResponse；Action 注册表把公开动作名映射为固定执行描述；Docker 与 Kubernetes 执行器分别通过可替换运行时客户端管理容器或 Job/Pod 生命周期。PostgreSQL、Attempt、Dispatch 和租约仍是业务事实源，容器 ID、Pod 名称和运行时日志只用于诊断。

**技术栈：** Go 1.26；Docker 官方 Go SDK；Kubernetes client-go；Docker Desktop；kubectl；kind；PostgreSQL 16；现有 Worker、Coordinator、faultinject、observability 和多进程 E2E 夹具。

## 全局约束

- 代码标识符保持英文，关键字段、资源限制、凭据、生命周期和故障边界使用规范中文注释。
- 默认单元测试不访问 Docker Engine、kind 集群、外部镜像仓库或外部网络；真实运行时测试显式检测前置条件。
- Action 只能来自固定注册表；工作流输入不能直接指定 Shell、镜像、宿主机路径、Docker Socket、Namespace 或任意网络地址。
- 容器默认非 root、只读根文件系统、禁止特权、禁止提权、不挂载宿主机目录、不挂载 Docker Socket，并设置资源和输出上限。
- Kubernetes Job 使用 backoffLimit=0；平台统一决定 Attempt 重试，不能叠加 Kubernetes 自己的业务重试。
- 日志、Trace 和结果不得写入 Token、密码、租约令牌、完整任务输入、模型提示词或敏感结果。
- 容器不是绝对安全沙箱；不承诺安全运行任意恶意代码、多租户强隔离或抵御内核/容器逃逸漏洞。
- 观测和运行时清理失败不得伪造业务成功，也不能绕过现有状态事务和租约校验。
- 不引入 Helm、Service Mesh、Operator、GPU、消息队列、缓存、微虚拟机或第二套服务端。
- 新增依赖必须与 Go 1.26 兼容，并在变更后运行全量测试、静态检查和文档门禁。
- 每个新增命令必须在命令块外逐条解释，命令块内只保留可执行命令。
- 不自动暂存、提交、创建 PR 或发布文章；模块完成后由用户手动提交和审核。
