# ADR-0001：项目范围与定位

- 状态：已批准
- 日期：2026-08-06

## 背景

项目需要同时满足学习分布式系统、形成求职作品、探索 AI/Agent 基础设施和验证产品价值的目标。讨论过延迟消息队列、API 网关、分布式作业调度、Agent 沙箱、搜索推荐系统和 Coding Agent 管理平台等方向。

## 决策

选择“面向 AI 与数据任务的可靠工作流编排与执行平台”作为项目主线。

分布式工作流是系统内核；Agent 受限执行和搜索/推荐数据流水线是用于验证内核价值的场景。系统同时支持单 Agent、多 Agent 和普通程序任务。

## 原因

- 能复用现有 Go、Kafka、Redis、时间轮和异常恢复经验；
- 能学习调度、状态机、分布式协调、容器和可观测性；
- 可覆盖 AI 后端、数据平台、Agent Infra 和分布式后端岗位；
- 不依赖双边市场；
- 可以在本地通过 Mock Agent 和模拟服务低成本验证；
- 即使 AI 产品形态变化，可靠任务执行能力仍然可迁移。

## 代价

- 项目范围较大，需要分模块实施；
- 已有成熟竞品，产品差异化尚未验证；
- 个人实验不能替代大规模生产经验；
- 多 Agent 不一定优于单 Agent，需要控制协调成本；
- 容器安全和分布式正确性需要严格测试。

## 未选择方案

- 纯延迟消息队列：范围较窄且竞品成熟；
- 纯 API 网关：差异化不足；
- 纯 Agent 沙箱：学习曲线和范围风险过高；
- 纯搜索推荐系统：岗位覆盖更专一；
- 纯 Coding Agent 管理平台：容易与现有工具能力重叠；
- 消费级双边平台：冷启动、获客和责任成本不符合个人项目约束。
