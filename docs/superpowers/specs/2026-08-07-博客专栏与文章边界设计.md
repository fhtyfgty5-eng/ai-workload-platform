# 博客专栏与文章边界设计

## 目标

让 CSDN 专栏能够清楚记录“从零开发一个新项目”的全过程，同时保留面向零背景读者的详细技术学习内容，避免博客正文混入 Codex 交接、仓库维护和文档验收信息。

## 专栏定位

专栏名称：`从0构建AI Workload Platform工程实践`。

专栏记录一个新项目从产品定义、架构学习、代码实现、测试实验到复盘的全过程。`AI Workload Platform` 是项目名称，不是本文要解释的通用行业术语。

## 文章分类

### 项目总览篇

开头必须明确“作者正在从零开发一个什么产品”。正文覆盖产品目标、目标用户、使用流程、典型场景、现有产品关系、待验证的差异化方向、技术路线和当前边界。

### 技术学习篇

围绕一个技术主题展开详细解释，保留术语、类比、示例、失败场景和替代方案。开头必须说明该技术在 AI Workload Platform 中解决什么具体问题，不能写成与项目无关的泛科普。

### 模块实践篇

只记录已经实现并验证的代码、测试、实验结果、失败过程和限制。尚未实现的内容必须标记为设计或假设，不能写成事实。

## 正文边界

博客正文不得包含：

- Codex 交接流程；
- README 阅读顺序；
- `项目状态.md` 字段；
- Git 提交和工作区过程；
- 文件目录管理约定；
- 文档验证脚本的文件数、链接数等仓库验收输出；
- 用户是否提出问题或确认内容的对话记录；
- 未真实发生的读者提问。

技术实验可以进入正文，但必须验证工作流技术行为，例如状态转换、依赖解锁、重试、超时、取消、恢复和幂等。实验记录必须包含环境、输入、命令、原始结果、结论和限制。

## 项目介绍与技术学习的关系

如果一篇文章同时承担“解释项目是什么”和“完整讲解多个技术概念”两个目标，应优先拆分为系列文章。项目总览篇负责建立产品认知，技术学习篇负责深度学习；不能为了简短删除必要的知识解释，也不能因为知识详细而隐藏项目定位。

模块 0 首先拆成两篇：

1. `从 0 构建 AI Workload Platform（一）：为什么做、做什么、与现有产品有什么不同`；
2. `从 0 构建 AI Workload Platform（二）：工作流、DAG、状态机与可靠执行基础`。

## 发布状态

文章正文必须可以直接复制到 CSDN，不包含内部发布元数据。发布状态、所属模块、专栏名称、验证结果、发布日期和公开地址统一记录在 `项目状态.md`。

## 新窗口约定

新窗口处理学习文章前必须：

1. 确认专栏定位和当前项目阶段；
2. 判断文章属于项目总览篇、技术学习篇还是模块实践篇；
3. 检查文章是否混入项目交接和仓库管理内容；
4. 检查项目总览篇是否明确这是一个从零开发的新项目；
5. 检查技术学习篇是否保留零背景解释，并说明技术在项目中的作用；
6. 当一篇文章承担两个独立目标时，先报告并建议拆分，不继续堆叠内容。

## 验收标准

- 学习资料规范、CSDN 模板和启动协议使用一致的文章分类和正文边界；
- 项目状态记录新专栏名称和两篇文章的草稿状态；
- 文章正文不再承担发布状态管理；
- 文档验证脚本和本地链接检查继续通过；
- 规则经用户审核后，才设计两篇文章的详细大纲。
