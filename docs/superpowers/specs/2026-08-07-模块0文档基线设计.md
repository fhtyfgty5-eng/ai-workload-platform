# 模块 0 文档基线设计

## 目标

补齐项目定义与交接基线，使新窗口能够按统一顺序恢复上下文，并让模块 0 具备可审核、可验证的文档交付物。

本轮不实现业务代码，不改变已批准的产品范围，不安装外部依赖，也不提交 Git。

## 文档职责

- `README.md`：项目入口、安全边界和统一阅读顺序。
- `docs/新窗口启动协议.md`：新窗口的只读检查、汇报和审核门槛。
- `项目状态.md`：当前事实、进行中工作、测试状态和最近交接。
- `docs/计划/模块0详细计划.md`：模块 0 的范围、交付物、验收与验证。
- `docs/学习/文章/模块0-术语与项目导览.md`：面向零背景读者的入门资料和博客草稿。
- `scripts/verify-docs.sh`：不联网、不改文件的文档基线验证命令。

信息流固定为：

`README -> 启动协议 -> 项目状态 -> 产品/架构/学习规范 -> 模块 0 计划 -> 模块 0 学习资料 -> 验证命令`

## 关键约定

### 阅读顺序

README 和启动协议使用同一顺序：README、项目状态、产品说明、架构基线、学习资料规范、项目路线图，然后是当前模块详细计划、学习资料、代码和测试。

### 状态字段

项目状态必须包含“当前阶段”“已完成”“正在进行”“下一步”“测试状态”和“最近交接”。最近交接记录日期、分支、最近提交、本次完成内容、尚未完成内容、阻塞或待确认问题、验证命令及结果、下一窗口动作。

### 学习资料

模块 0 导览面向没有工作流或分布式系统背景的读者。专业名词首次出现时给出英文全称和中文解释；技术选型至少说明当前问题、选择原因、两种以上替代方案、代价和更换条件。

准备写成博客的学习资料统一保存在 `docs/学习/文章/`，通过文章头部元数据记录“草稿”“可发布”或“已发布”，不因状态变化移动文件。文章达到“可发布”状态时必须主动提醒用户。

### 验证接口

执行 `scripts/verify-docs.sh [项目根目录]`。省略参数时使用脚本所在仓库根目录；退出码 `0` 表示必需文件存在、没有冲突标记、本地 Markdown 链接可解析且 `git diff --check` 通过；非 `0` 表示至少一项失败，并打印失败项。

## 不在本轮范围内

- Go 工作流内核、调度器、状态机和 Agent 适配器；
- PostgreSQL、Redis、Kafka、容器运行时或 Kubernetes；
- 真实模型 API、业务数据和外部部署；
- 修改 `docs/决策/ADR-0001-项目范围.md`；除非用户另行批准范围变更。

## 验收标准

1. README 与启动协议的阅读顺序一致。
2. 状态文件包含协议要求的全部字段，并能反映当前未提交的真实状态。
3. 模块 0 有独立详细计划和可独立阅读的术语导览。
4. 验证脚本可在当前仓库通过，并能对缺失文件、冲突标记和坏链接给出失败结果。
5. 工作区没有业务代码或外部依赖变更。
