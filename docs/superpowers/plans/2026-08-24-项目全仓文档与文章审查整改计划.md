# 项目全仓文档与文章审查整改计划

> **For agentic workers:** 本计划只涉及文档、文章和项目状态整理，不修改业务代码、公开 API 或数据库结构。步骤使用复选框跟踪，并在模块级统一交由用户审核。

**目标：** 修正项目事实与路线漂移，重构模块 3 文章主线，统一学习资料规则，并明确历史文档与当前文档的职责边界。

**架构：** 以 `项目状态.md` 作为当前事实入口，以 README、产品说明、架构基线和路线图作为项目级设计入口；学习文章只面向读者解释技术，不承担交接和历史过程记录；`docs/superpowers/` 作为历史过程归档，不再作为当前设计依据。

**技术栈：** Markdown、现有 Bash 文档验证脚本、Go 全仓测试、Go race detector、`go vet`；不增加第三方依赖。

## 全局约束

- 不修改 `workflow/`、`agent/`、`internal/`、`pkg/`、`cmd/` 下的业务代码。
- 不改变公开 CLI、HTTP API、SDK、数据库迁移或示例 JSON 的行为。
- 文章面向零背景读者，首次出现的专业名词必须解释。
- 默认不使用生活类比；使用直接定义、具体输入输出、数据流和状态变化说明机制。
- 文章正文不得包含 Git、Codex、交接流程、虚构读者问题或文档验收过程。
- 明确区分设计目标、已实现内容、实测结果和限制。
- 不删除历史计划；只增加归档说明，避免误把历史记录当作当前状态。
