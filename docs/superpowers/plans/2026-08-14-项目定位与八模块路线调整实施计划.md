# 项目定位与八模块路线调整实施计划

> **执行要求：** 本计划在当前会话内逐项执行；完成整个文档模块后暂停，等待用户审核。未经用户明确批准，不提交 Git、不开始模块 1 业务实现，也不处理 Git 历史。

**目标：** 将项目统一调整为“面向 Agent 与确定性程序任务的可靠运行时和调度平台”，并把原 10 个模块重排为依赖关系清晰的 8 个模块。

**架构：** 继续以模块 1 的单机可靠工作流内核为基础，后续依次增加控制面与数据库、Agent Runtime、多 Worker、可观测性与故障验证、受限执行环境与 Kubernetes，最后通过真实场景和开源发布完成验证。自然语言生成工作流降为可选产品能力，不再阻塞可靠执行主线。

**技术栈：** Markdown、Bash、Python 3 标准库、Git 文档检查。

## 全局约束

- 模块 1 学习文章仍是“草稿，待用户审核”，本轮不修改正文。
- 模块 1 已批准的状态机、DAG、重试、恢复和性能设计保持不变。
- 性能验证从模块 1 开始持续执行，不推迟到可观测性模块。
- 开源准备从现在开始建立检查边界，但许可证和治理文件留到第二批单独确认。
- 新增普通项目文档优先使用中文文件名；GitHub 自动识别的标准治理文件未来保留英文名。
- 不自动暂存或提交 Git。
