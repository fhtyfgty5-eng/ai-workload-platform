# Module 0 Documentation Baseline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task after user approval. Do not commit until the user has manually approved the final diff.

**Goal:** 补齐模块 0 的文档、入门资料、交接字段和只读验证，使项目可以稳定地交接给下一窗口。

**Architecture:** 以现有 Markdown 文档为事实载体，按 README、启动协议、状态、领域说明、模块计划、学习资料的单向信息流组织内容。使用一个无网络、无第三方依赖的验证脚本检查文档基线，不引入业务运行时。

**Tech Stack:** Markdown；Bash；Python 3 标准库（仅用于解析本地 Markdown 链接）；Git 内置 `diff --check`；现有 `rg`。

## Global Constraints

- 当前阶段仍为模块 0；未获得用户批准不得进入模块 1。
- 本轮不写业务代码、不安装依赖、不部署服务、不改变已批准范围。
- 学习资料面向没有相关背景的读者；专业名词首次出现必须解释英文全称和中文含义。
- 每项技术必须说明选择原因、至少两种替代方案、代价和更换条件。
- 验证命令必须可在没有外部网络和模型 API 的情况下运行。
- 不提交 Git；完成后先给出 diff 摘要并等待人工审核批准。

- Modify: `README.md`：统一入口阅读顺序。
- Modify: `docs/新窗口启动协议.md`：补全必读资料和缺失项报告规则。
- Modify: `项目状态.md`：补充进行中、测试状态和完整交接信息。
- Create: `docs/计划/模块0详细计划.md`：模块 0 计划与验收清单。
- Create: `docs/学习/文章/模块0-术语与项目导览.md`：零背景入门资料和博客草稿。
- Create: `scripts/verify-docs.sh`：文档基线验证入口。
- Create: `scripts/test-verify-docs.sh`：验证脚本的临时目录回归测试。
