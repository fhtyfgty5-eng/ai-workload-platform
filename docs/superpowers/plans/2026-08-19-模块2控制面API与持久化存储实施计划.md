# 模块 2 控制面 API 与持久化存储实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. 任务级质量门禁通过后连续执行，模块完成后由用户统一审核；Codex 不自动暂存或提交 Git。

**Goal:** 在复用模块 1 单套可靠工作流 Engine 的基础上，交付一个使用 PostgreSQL 的单实例 HTTP 控制面，支持不可变工作流版本、异步幂等 Run、状态查询、取消、自动恢复、基础鉴权、Go SDK 和可复现本地环境。

**Architecture:** 保留 `workflow` 包作为唯一状态机和调度实现，新增增量持久化变更集；FileStore 通过兼容适配器继续保存完整快照，PostgreSQL Repository 将同一变更集写入关系表。`internal/app` 负责资源和业务语义，`internal/httpapi` 负责 HTTP 契约，`cmd/workload-server` 负责配置、迁移检查、Advisory Lock 和恢复，`pkg/workloadclient` 负责 Go SDK。

**Tech Stack:** Go 1.26、Go 标准库、PostgreSQL 16、`github.com/jackc/pgx/v5`、`pgxpool`、Docker Compose、SQL migrations、`encoding/json`、`net/http`、`httptest`、Go `testing`、OpenAPI 3.1。

## 全局约束

- Go module 路径固定为 `github.com/fhtyfgty5-eng/ai-workload-platform`，最低 Go 版本保持 `go 1.26.0`。
- PostgreSQL 是模块 2 第一实现；不同时维护 MySQL 实现，不提前加入 Redis、Kafka、gRPC、API Gateway 或复杂可观测性平台。
- 模块 2 只支持一个控制面实例；使用 PostgreSQL Advisory Lock 防止第二个协调者启动，不把它描述为高可用或多 Worker 租约。
- Workflow 定义与 Run 分离；首次创建 Workflow 原子创建 `version=1`，后续修改只能创建新版本；Run URL 必须显式指定版本。
- 创建 Workflow、创建版本和启动 Run 必须先调用模块 1 `Compile`；PostgreSQL 保存完整定义 JSON，不保存编译后的数组索引。
- Run 启动异步返回 `202 Accepted`；创建版本和启动 Run 必须携带 `Idempotency-Key`，相同 Key 加不同请求内容返回 `409 Conflict`。
- 运行状态使用 `workflow_runs`、`task_runs`、`attempts`、`state_events` 关系表；一次状态变化通过一个 PostgreSQL 事务提交。
- `revision` 和连续事件序号用于乐观并发控制；旧状态不能覆盖新状态；事务失败时不启动新 Attempt、不解锁下游。
- 服务启动必须先连接数据库、检查迁移、取得 Advisory Lock、恢复非终态 Run，之后 `ready=true`；未就绪时拒绝业务请求。
- Bearer Token 由环境变量或 Secret 注入，角色只有 `viewer` 和 `operator`；不实现登录、注册、OAuth/OIDC 或 Token 签发。
- 默认执行器是 Mock Executor，不执行本机命令、不调用真实模型、不访问外部网络。
- Docker Compose 只负责启动开发 PostgreSQL；Go 服务和任务默认在本机运行，不把它描述为任务容器化或安全沙箱。
- SDK 不自动重试写请求；调用方重试必须复用原 `Idempotency-Key`。
- 新增导出标识符使用英文 Go Doc；复杂字段、事务顺序、锁、状态不变量和安全边界写中文注释；不保留与实现不一致的过期注释。
- 行为修改严格执行 RED、确认预期失败、GREEN、全量回归、REFACTOR；每个任务都必须有自动化测试。
- 每个任务完成后执行相关测试、全量回归、代码自审和状态同步，通过后直接进入下一任务，不暂停等待用户人工审核。
- 改变已批准的需求、公开接口、数据模型、安全边界或技术选型时必须暂停确认；安装软件、处理真实凭证、访问外部服务或执行破坏性操作前仍须单独确认。
- 模块 2 全部任务和最终验证完成后统一交由用户审核；审核通过后由用户手动提交 Git，Codex 只提供合适的中文 commit 描述。
- 所有任务完成前不得宣称模块 2 完成；最终必须运行 `go test ./...`、`go test -race ./...`、`go vet ./...`、数据库集成测试、两项文档验证和 `git diff --check`。

```go
type ChangeSet struct {
	RunID            RunID
	ExpectedRevision uint64
	Run              *WorkflowRun
	Tasks            []TaskRunChange
	Attempts         []AttemptChange
	Events           []StateEvent
}

type TaskRunChange struct {
	RunID                 RunID
	Index                 int
	Task                  TaskRun
	RemainingDependencies int
}

type AttemptChange struct {
	RunID     RunID
	TaskKey   TaskKey
	TaskIndex int
	Attempt   Attempt
	Operation ChangeOperation
}

type ChangeOperation string

const (
	ChangeInsert ChangeOperation = "insert"
	ChangeUpdate ChangeOperation = "update"
)

type Persistence interface {
	Create(context.Context, RunSnapshot) error
	Apply(context.Context, ChangeSet) error
	Load(context.Context, RunID) (RunSnapshot, error)
	ListNonTerminal(context.Context) ([]RunID, error)
	RequestCancel(context.Context, RunID, time.Time) (WorkflowRun, error)
}
```

`WorkflowRun` 增加 `Revision`、`LastEventSequence` 和 `CancelRequestedAt`；`ChangeSet` 只包含当前状态变化影响的行。FileStore 的 `Apply` 通过加载、校验 expected revision、替换完整快照实现兼容行为。

模块 1 原有 `Store` 继续保留 `Create`、`Save` 和 `Load`；新增只含 `Create`、`Load` 的 `RunStore` 作为完整快照 Store 与增量 Persistence 的共同边界。测试辅助实现集中在 `workflow/persistence_test.go`：`deltaTestStore` 记录 ChangeSet，`applyOnlyTestStore` 证明 PostgreSQL 风格存储不需要实现 `Save`。这些辅助实现不替代 FileStore 或 PostgreSQL 集成测试。
