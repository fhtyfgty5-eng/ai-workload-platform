# 模块 2 控制面性能基线

## 目的

本基线测量模块 2 单实例控制面在本机开发环境中的最小 HTTP/PostgreSQL 路径，用于后续代码修改时做相同输入的回归比较，不作为生产性能承诺。

## 环境

- macOS，Apple M4，10 个逻辑 CPU，32 GiB 内存；
- Go 1.26；
- PostgreSQL 16，Docker Desktop 本地容器；
- HTTP 使用本机回环地址，不启用 TLS；
- 每项基准使用独立临时数据库，测试后删除。

## 输入与口径

- Workflow 只有 1 个无依赖任务；
- 定义已经创建，运行时命中进程内编译缓存；
- `GetRun/sequential`：串行执行 100 次 HTTP Run 摘要查询；
- `GetRun/parallel`：使用 Go `RunParallel` 在 10 个逻辑 CPU 上共同完成 100 次查询；`ns/op` 是总耗时折算到每次操作的吞吐口径，不是单请求延迟分位数；
- `StartRun`：串行执行 100 次 HTTP Run 创建，每次使用不同 RunID 和幂等 Key；事务写入 1 个 Run、1 个 TaskRun、初始事件和幂等记录；
- StartRun 基准关闭后台执行，只测量认证、HTTP/JSON、应用服务和初始 PostgreSQL 事务，不包含任务执行时间。

运行命令：

```bash
TEST_DATABASE_URL='postgres://workload:workload_dev_only@localhost:5432/workload?sslmode=disable' \
go test ./internal/e2e -run '^$' -bench '^BenchmarkControlPlane' \
  -benchmem -benchtime=100x -count=5
```

`TEST_DATABASE_URL` 对应的测试用户需要拥有创建和删除临时数据库的权限。仓库提供的 Docker Compose 本地用户满足该条件。

## 汇总

| 场景 | 五轮平均 | 平均分配 |
| --- | ---: | ---: |
| Run 串行查询 | 0.281 ms/op | 12.29 KiB/op，158 allocs/op |
| Run 并行查询 | 0.081 ms/op | 19.38 KiB/op，约 177 allocs/op |
| 创建 pending Run | 1.234 ms/op | 19.61 KiB/op，296 allocs/op |

并行查询的第一轮包含连接池和运行环境预热影响，波动明显高于后四轮，因此不能把平均值解释为稳定的单请求延迟。

## 结论与限制

当前输入下，控制面查询和单任务 Run 创建没有暴露毫秒级以上的本机固定开销，适合作为模块 2 的首轮回归基线。这个结论不能外推到多任务定义、长事件历史、跨机器数据库、TLS、磁盘压力或大量并发写入。

本基线没有测量 P50、P95、P99 尾延迟，没有寻找连接池或数据库饱和点，也没有测量后台 Engine 执行带来的竞争。模块 5 进入系统性能验证时，应增加多任务、多并发、长历史、故障注入和资源监控，并与本基线使用相同输入做对照。
