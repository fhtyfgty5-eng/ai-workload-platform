全仓普通测试在受限沙箱中曾因 `httptest` 无法绑定 IPv6 本地端口而失败；该失败来自执行环境权限，不是 Go 断言失败。模块 6 相关包和真实 Docker E2E 已在允许 Docker/本地监听的环境重新运行通过。最终全仓质量门禁需要在同样允许本地监听的环境中重跑。

## 4. Docker 真实执行证据

命令：

```text
bash scripts/run-module6-docker.sh
```

结果：

```text
module six
image=sha256:0f9f4012834e6de824e63820a69a1cd13ac192fd2e78929e332823e6149c8432
```

脚本使用 `scratch` 镜像，动作以 Linux ARM64 静态二进制运行，约束包括：

- network none；
- 非 root UID 65532；
- 只读根文件系统；
- `no-new-privileges`；
- 删除全部 capability；
- CPU 0.25、内存 64 MiB、PIDs 32；
- 8 MiB、noexec、nosuid 的 `/tmp` tmpfs；
- 不挂载宿主机目录和 Docker Socket。

Go 级真实 Docker 测试返回 `success`，输出为 `docker ok`。本次报告没有把超时、OOM 和输出超限写成真实 Docker 数值证据；这些边界已有 Fake 客户端和结构化结果映射测试，完整资源故障实验仍是后续可重复实验项。

## 5. Kubernetes 真实验证证据

已通过：

- JobSpec 单元测试：固定命名空间、Job 名称、标签、资源和 `backoffLimit=0`；
- client-go 对象映射代码编译和 Fake 客户端测试；
- Kubernetes 清单静态检查：未发现 Token、私钥、宿主机路径、hostPath、Docker Socket、特权或自动挂载 ServiceAccount Token；
- `kindest/node:v1.36.1` 节点镜像导入本地后，kind v0.32.0 成功创建 `workload-local` 集群；
- Kubernetes 客户端和服务端均为 v1.36.1，控制节点为 `Ready`；
- 固定清单 Job 成功完成，日志为 `kubernetes action`，随后定向删除 Job；
- `KubernetesExecutor` 通过 client-go 真实创建 Job、等待完成、读取 `kind ok` 并清理，测试约 2.8 秒通过；
- 32 MiB 内存限制下执行 64 MiB 分配，Pod 以 `OOMKilled`、退出码 137 结束；真实 client-go 测试把它映射为 `temporary_failure / oom_killed`；
- 运行中删除 60 秒 CPU 动作 Pod 后，Job 因 `backoffLimit=0` 进入 Failed，没有由 Kubernetes 创建隐式业务重试；
- 实验结束时 `workload-tasks` 命名空间没有残留 Job 或 Pod，默认拒绝出口的 NetworkPolicy 仍存在。

未完成：

- 默认 kind CNI 是否实际执行 NetworkPolicy 的出口拒绝；
- CPU 限流和临时存储超限的真实 Pod 事件；
- 删除 Pod 后由平台状态机创建新 Attempt，以及终止 Worker 后的租约回收、重新分配和迟到结果拒绝；
- Kubernetes Worker、控制面和 PostgreSQL 的完整进程级故障链路。

## 6. 安全和开源检查

代码和清单不接受任意用户 Shell、任意镜像、宿主机路径、Docker Socket 或 Namespace。日志和错误码不写入 Token、密码和完整输入。实验脚本只创建带模块 6 名称的本地资源，不执行宽范围删除。

容器配置是降低风险的工程边界，不是绝对安全沙箱。模块 6 不承诺恶意代码隔离、多租户安全、内核漏洞防护或生产 Kubernetes 高可用。

## 7. 结论

模块 6 已完成固定 Action 注册表、Docker/Kubernetes 执行器抽象、Docker 真实动作验证、Kubernetes 清单、kind 固定 Job、client-go 成功路径、OOM 映射和 Pod 删除后的 Job 失败边界。剩余 NetworkPolicy 实际阻断、CPU/临时存储和完整平台故障恢复实验不影响成功链路，但会限制对 Kubernetes 安全隔离和故障恢复的结论。后续模块 7 可以在不改变这些执行边界的前提下接入轻量 Web 控制台。
